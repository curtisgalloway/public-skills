# L02c: verify the spec and measure recall

## Terms

- **Spec** — the clean-room implementation spec for the Intel 82540EM (e1000) core network path,
  written in [L02b](L02b.md).
- **Reading** — one verifier subagent's pass over the spec, giving each tagged fact a verdict:
  `PASS`, `FAIL`, `UNVERIFIABLE` (its authority could not be read), `GAP`, or `ADJUDICATE`
  (two readings disagree and someone has to decide).
- **Verification record** — the file holding those verdicts, kept beside the spec, never loaded
  by an implementer (`spec-verifier`).
- **Blind requirement list** — the 66 active requirements written from the Intel manual in
  [L02a](L02a.md) before the spec existed.
- **Recall** — the share of the blind list the spec states.
- **Transfer review** — the `cleanroom-spec` gate: leak scan, leak judgment, structure,
  attractants (source file paths or "the driver does X" narration that would tempt a reader
  back to the source), and the usage notice. It does not judge accuracy.
- **HALF 1 / HALF 2** — the spec's two parts: the hardware (from the manual and standards) and
  the Linux integration (from kernel `include/` and `Documentation/`).

See the [glossary](../../../GLOSSARY.md), the [design](../QEMU-DIFFERENTIAL.md) (A1, D4), and the
[plan](../IMPLEMENTATION-PLAN.md) (L02c).

### Errors found in revision 3

| Claim | Found by | Error | Revision 4 |
| --- | --- | --- | --- |
| CTRL.FD initial value | B; confirmed by a third reader on the rendered page | The spec gave 0. Table 13-3 gives 1b for the 82540EM; 0b is footnoted for other parts only. | 1b |
| Statistics not hardware-initialized | A and B | Said another manual section disagrees "for newer parts"; that section names no parts. | States the disagreement plainly; follows §13.7 |
| PHY address | A and B | Said only address 1 responds, so don't scan. The manual says only that the internal PHY is at address 1. | Use address 1 directly |
| 64-bit statistics op | A (B passed it with a note) | Cited kernel documentation lines for the older op. | Corrected citation |
| Ring alignment | B | Cited allocator prototypes, which don't state alignment. | Cites the DMA API guide (range fixed in the follow-up) |
| Gotcha G-16 | B | Labeled printed page numbers as PDF pages. | Both given |

Three of these are about what the hardware does (FD, the PHY address) or what the manual says
(the statistics note); three are citation defects. The four split verdicts were put to the user, who chose a third reader for CTRL.FD and accepted the three citation fixes as
FAILs.

UNVERIFIABLE (4): the IEEE 802.3 clause mapping of PHY registers, INTx signaling (two places),
and the 802.3 Annex 28B pause table. Each rests on a standard that neither reader was allowed to
fetch, and the manual does not restate it.

- Omissions the readers proposed (both: the interrupt-rate sentence and RDTR; B only: EEPROM

  meets §14.4); re-applying EEPROM-default CTRL bits after reset (explained, with citations, as
  already covered); and re-citing facts that leaned on a manual section limited to other parts.

The three partial rows, all critical:

- **E1000-PCI-002** — no mention of BAR0's type field or of reading it. Added in revision 4.
- **E1000-RX-007** — completion by DD stated only as an ordering rule, not "don't read RDH".
  Added in revision 4.
- **E1000-INIT-005** — the row asks for transmit ring registers to be written before TCTL.EN as a
  requirement; the spec calls that order "not known to be required". The assessor found the
  manual's §14.5 supports the spec, so this is recorded as a list row that overstates the
  manual, not a spec gap. The frozen list is unchanged.

The assessor also noted that the spec's CTRL.SPEED row and row INIT-004 read one bit's
condition differently; the spec's procedure clears both bits involved, so it has no effect.

file beside it so the hash still holds. The per-row table is

## Review method

The spec's readings, checks, and transfer review were fresh Claude Opus 5.5 subagents, the same
model family as the spec's author, as the plan's `spec-verifier` method specifies. The review of
these public changes used the plan's documentation method, `consult` with Codex, which was
available again (it was not in L02b); it is recorded in the next section.

## Limits

- Revision 4 as a whole has not had two full readings. Its 51 changed claims had one, and the
  follow-up's one line was checked only by `diff`. Everything else is as verified in revision 3.
- Recall was measured once, by one assessor, on revision 3. It was not re-measured on revision 4.
- All readers share a model family with the author, and that model may have seen the Linux
  e1000 driver in training.
- The PCI and IEEE 802.3 standards were never read; the four claims that rest on them only are
  plausible, not verified.
- Subagent transcripts are recorded by path in the run's ledger. Those paths are temporary files
  that are not retained.
