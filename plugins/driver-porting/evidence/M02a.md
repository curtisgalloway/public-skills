# M02a: environment entry and evaluator build

## Terms

- **Evaluator** — the preparation side allowed to inspect reference implementation material.
- **Guest** — a Linux system running through the container runtime.
- **Initramfs** — a small initial filesystem loaded into memory with the kernel.
- **Netboot** — fetching boot files over the network before starting the operating system.

See the [glossary](../../../GLOSSARY.md) and
[M01 preparation contract](../evals/enc28j60/reconstruction/M01-PREPARATION-v1.md).

A separate board-expert investigation initially derived the netboot and pin recommendations

Connect by printed signal labels, not assumed module-header positions. Preserve physical
pins 8/10 for the existing serial console. Keep wires short and wire with power off. Do not
connect the module's VCC to the Pi's 5 V supply. If the actual connector is labeled 5 V instead
of VCC/3.3 V, resolve that discrepancy before powering it. J1-8 RESET, J1-1 CLKOUT and J1-3 WOL
remain unconnected. The drawing shows R2 pulling RESET up to VCC through 10 kΩ; no GPIO-driven
reset is proposed. SCK is the SPI clock input and is distinct from CLKOUT. Module reset behavior,
supply integrity and GPIO occupancy still require physical qualification. The supplied schematic
is integration evidence only, not a permitted new hardware-behavior document for the implementer.
Its minimal supplied facts must pass the outside-spec inventory/audit before export.

The user-supplied schematic (origin not independently verified) is 161,654 bytes, SHA-256
`d23bf8886a24736f4d1e15822604b2a9ff638489f22e09dfa8a0950a9086a3ff`.
It remains outside the repository; no public redistribution or indefinite retention is claimed.

Netboot requires pinned Pi 4 firmware assets, explicit kernel/DTB selection and a chosen root
filesystem. Upstream `defconfig` has `BCMGENET=m` and `SPI_BCM2835=m`; NFS root (a network-mounted filesystem)
therefore needs built-in network dependencies or an initramfs that loads them. A RAM filesystem
is the recommended next candidate because it can be identified as one immutable artifact and
does not need a live NFS server during testing. Keep it minimal to fit the recorded 2 GB board;
a full distribution image is not the proposal. It is not built or selected as final here.
Existing boot assets need an inventory, preserved copies, a tested restore procedure and an
exclusive fixture lease before a separately authorized Linux boot. No EEPROM change is proposed.
Hardware boot qualification remains M06. Firmware parameters and UART behavior must be verified
against the upstream DTB; do not assume downstream overlays work with it unchanged.

Power-current margin, rail stability under transmit load, short SPI wiring and actual peer
duplex/capture capabilities remain fixture qualifications, not proven by this diagram. Pin 1
remains the chosen 3.3 V supply connection; pin 17 is an electrically valid alternative, not
a required correction. INT polarity/trigger and maximum SPI clock need explicit outside-spec
dispositions rather than undocumented facts supplied during implementation.
