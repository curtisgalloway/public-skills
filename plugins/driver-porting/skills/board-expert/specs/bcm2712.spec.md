# Broadcom BCM2712

## Orientation

The BCM2712 is the Raspberry Pi 5 / Compute Module 5 application processor: Cortex-A76 cores, an
on-SoC peripheral window placed very high in the physical map, a GIC-400, and VideoCore firmware that
owns clocks and power. Most board I/O is not on this chip at all; it sits on the RP1 southbridge across
PCIe (see the `rp1` spec). There is no public BCM2712 peripherals datasheet, so the device tree is the
primary public address map and the BCM2711 datasheet is the register-level proxy for shared IP.

## Quick-facts

- **Addressing model.** Peripherals sit very high: the on-SoC peripheral window is exposed to the ARM
  cores at base `0x10_0000_0000`, and legacy `0x7x_xxxxxx` numbers are *offsets*, so
  `physical = 0x10_0000_0000 + offset`. All address math must be 40-bit-clean. `[DT]`
  (`bcm2712.dtsi`, `soc` node `ranges`).
- **`soc` `ranges` cell trap.** The root node is `#address-cells = 2` / `#size-cells = 2`; the `soc`
  node is `1` / `1`. A `ranges` tuple is `[child: 1 cell][parent: 2 cells][size: 1 cell]`. Assuming
  the child inherits the root's two cells silently yields a wrong or identity translation, a classic
  bring-up bug; do the arithmetic explicitly. `[DT]` (`bcm2712.dtsi`), `[standard]` (device-tree
  specification, `ranges` semantics).
- **Boot chain and entry state.** VPU boot ROM → SPI-EEPROM bootloader → armstub (TF-A BL31) + DTB +
  OS image (BL33). BL31 at EL3 installs PSCI over SMC, patches the DTB (PSCI node, reserved-memory for
  itself), and ERETs to the image at **EL2, AArch64, MMU off, D-cache off, `HCR_EL2.VM = 0` (no
  stage 2), DTB pointer in `x0`**. The low 512 KiB (`0x0`–`0x80000`) is resident TF-A: do not
  overwrite it or map it cacheable. `[doc]` (TF-A rpi5 platform page), `[standard]` (Linux arm64
  `booting.rst`, the entry-state contract).
- **SMP topology.** Four Cortex-A76 cores. Secondary cores start via PSCI `CPU_ON`; there is no
  spin-table. CPU `reg` values `0x000` / `0x100` / `0x200` / `0x300` are MPIDR affinities (Aff1 =
  core). `[DT]` (cpu nodes and `psci { method = "smc" }` in `bcm2712.dtsi`), `[standard]` (PSCI
  DEN 0022).
- **Interrupts.** Standard GIC-400 (GICv2). GICD at `0x10_7FFF_9000`, GICC at `0x10_7FFF_A000`. DT IRQ
  encoding `<type number flags>`: SPI → INTID `32 + number`, PPI → INTID `16 + number`. `[DT]`
  (`bcm2712.dtsi` gic node), `[standard]` (GICv2 IHI 0048, the INTID spaces).
- **Debug UART.** ARM PL011 `uart10` at `0x10_7D00_1000`, left enabled by firmware;
  `earlycon=pl011,0x107d001000,115200n8`. Register model per the PL011 TRM. `[DT]` (`bcm2712.dtsi`),
  `[databook]` (DDI 0183). IRQ number and pinmux: `TODO (verify on hardware)`.
- **Timers.** ARM generic timer; the frequency is firmware-set, so read `CNTFRQ_EL0` rather than
  hard-coding it. `[standard]` (ARMv8-A ARM), `[hardware]` (54 MHz observed on a Pi 5). PPI numbers:
  `TODO (verify on hardware)`.
- **Clocks and power.** Firmware-owned. Most clocks, voltages, and power domains are managed by the
  VideoCore firmware through the mailbox property channel at `0x10_7C01_3880`; only a few fixed clocks
  are in the DT (`clk_osc` 54 MHz, `clk_uart` 9.216 MHz). `[DT]` (`bcm2712.dtsi` mailbox and
  fixed-clock nodes), `[databook]` (BCM2711 datasheet for the mailbox register model, as proxy).
- **GPIO and pinmux.** The 40-pin header is RP1; see the `rp1` spec. `[DT]` (`rp1.dtsi` as included
  by the board `.dts`). On-SoC GPIO bank addresses and the pinctrl compatible: `TODO (verify on
  hardware)`.
- **DTB runtime patching.** `/memory` (real RAM size), `/chosen` (`bootargs`, `stdout-path`),
  `aliases` (`serial0` → debug UART), the PSCI node, and `reserved-memory` are injected or filled by
  the firmware and BL31. Parse the live DTB; do not trust the static `.dts` for these. `[doc]` (TF-A
  rpi5 platform page for BL31's edits; Raspberry Pi documentation for the firmware's).

## Gotchas

- Do not look for peripherals at `0xFExxxxxx`; that is the Pi 4 (BCM2711). Everything moved high.
  `[DT]`
- You run at EL2, not EL1: use the `*_EL2` system registers (`VBAR_EL2`, `CNTHP_*`, `SCTLR_EL2`,
  `TCR_EL2`, `MAIR_EL2`), and verify `CurrentEL` rather than assuming. `[doc]` (TF-A rpi5 page)
- After the BL31 hand-off the MMU is off and there is no stage 2, so accesses are flat physical. If
  two code paths disagree about whether an address works, suspect different computed addresses, not a
  translation regime. `[doc]` (TF-A rpi5 page), `[standard]` (ARMv8-A ARM)
- No spin-table for SMP; PSCI only. Older Pi bring-up guides that poke per-core release addresses do
  not apply. `[DT]`
